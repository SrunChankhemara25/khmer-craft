# Deploying KhmerCraft to Render (public test link)

Goal: three public URLs your teacher can open with nothing installed.

| Service | URL | Sleeps? |
|---|---|---|
| Marketplace | `https://khmercraft-web.onrender.com` | No |
| Seller portal | `https://khmercraft-seller.onrender.com` | No |
| API | `https://khmercraft-api.onrender.com` | Yes, after 15 min idle |

**Send your teacher the marketplace URL.** The first page load after a quiet
period takes about 50 seconds while the free-tier API wakes up; everything
after that is normal speed.

## Why three services and not one

The marketplace and the seller portal are the same Angular bundle served from
two different origins. `core/portal/portal.ts` decides which site a tab is
showing by comparing `location.origin`. Put both on one origin and the
boundary guard redirects every route to itself, forever. Locally the two
origins are `localhost:4200` and `seller.localhost:4200`; on Render they are
two static sites.

The static sites never sleep, so the UI is always instant. Only the API is a
web service, so only the first API call after an idle period is slow.

## Steps

### 1. Create the Render account
Sign up at <https://render.com> with your GitHub account and authorise it to
read `SeoulDoriot/LukDo`. The repo is private; Render needs that permission.

### 2. Create the Blueprint
Dashboard → **New** → **Blueprint** → pick `SeoulDoriot/LukDo`.

**Set the branch to `merge-into-develop`** — Render defaults to the repo's
default branch, which is not where this work lives.

Render reads `render.yaml` from the repo root and proposes the three
services. Approve it.

### 3. Fill in the environment variables
Render will stop and ask for every value marked `sync: false`. Nothing secret
is committed, so these are typed once into the dashboard.

**khmercraft-api**

| Key | Value |
|---|---|
| `CORS_ALLOWED_ORIGINS` | `https://khmercraft-web.onrender.com,https://khmercraft-seller.onrender.com` |
| `API_PUBLIC_URL` | `https://khmercraft-api.onrender.com` |
| `MONGODB_URI` | your Atlas connection string |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `465` |
| `SMTP_USER` | the Gmail address that sends verification codes |
| `SMTP_PASSWORD` | the Gmail **App Password** |
| `MAIL_FROM` | same address, e.g. `KhmerCraft <you@gmail.com>` |
| `PAYWAY_MERCHANT_ID` | from ABA |
| `PAYWAY_API_KEY` | from ABA |
| `PAYWAY_CALLBACK_URL` | leave unset — it is derived from `API_PUBLIC_URL` |

`JWT_SECRET` is generated by Render automatically. Do not reuse the local one.

**khmercraft-web** and **khmercraft-seller** — identical values on both:

| Key | Value |
|---|---|
| `KC_API_URL` | `https://khmercraft-api.onrender.com` |
| `KC_MARKETPLACE_URL` | `https://khmercraft-web.onrender.com` |
| `KC_SELLER_PORTAL_URL` | `https://khmercraft-seller.onrender.com` |

If Render assigns different names (because yours are taken), use the real
URLs it shows and keep all five values consistent.

### 4. Allow Render to reach Atlas
MongoDB Atlas → **Network Access** → add `0.0.0.0/0`.

Render's free tier has no fixed outbound IP, so there is nothing narrower to
allow-list. This is acceptable for a test deployment because the database
still requires the username and password. Do not leave it open for a real
production launch.

### 5. Deploy and check
First build takes roughly 5–10 minutes. Then:

```
curl https://khmercraft-api.onrender.com/health
```

Expect `200`. Then open the marketplace URL.

## Known limitations of this deployment

- **Products load slowly.** `/api/products` returns ~3.9 MB because images are
  stored as base64 inside the documents. This is the biggest real problem with
  the app and it is not caused by Render.
- **Paid plans cannot be taken.** ABA PayWay answers
  `code 21, "End of API lifetime"` to every request — the sandbox credentials
  have expired. Sellers can still create a store on the free Starter plan via
  "Skip for now".
- **Most admin pages are mock data.** Only Products, Sellers, Stores and
  Storefront Websites read the real database.
- **The API sleeps.** First request after 15 idle minutes takes ~50 s.

## Before a real launch (not needed for teacher testing)

1. Rotate the Atlas password, the SMTP app password and the PayWay key —
   anything that has been on a developer machine should not guard production.
2. Replace `0.0.0.0/0` in Atlas with a fixed egress IP.
3. Confirm `ADMIN_GUARD_ENABLED` is `true` in `apps/web/src/app/admin/admin.guard.ts`.
4. Fix the base64 image storage.
